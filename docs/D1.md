# Talks in D1

`data/villages/*.json` stays the master copy. Public edits are still pull requests against those files. Nobody edits the database by hand.

On a push to `main` that changes village JSON, event metadata, the track list, or view counts, `.github/workflows/sync-talks.yml` upserts the changed talks into D1. The same script can rebuild the whole database from the repo:

```bash
npx tsx scripts/d1/sync.ts --full
npx tsx scripts/d1/sync.ts
npx tsx scripts/d1/sync.ts --files data/villages/defcon-30-retail-hacking.json
```

The first command loads every talk. The second loads only village files that differ from `HEAD` (and deletes talks removed from those files). Running either command twice with the same JSON does not create duplicate rows.

The preview worker is `wrangler.d1-preview.jsonc` (`cybertalks-d1-preview`). It has its own D1 database, `cybertalks-d1-preview`, and no custom domains. `wrangler.jsonc` is unchanged.

Talk, speaker, and topic pages read `TALKS_DB` when that binding exists. The homepage index and summary search read `/api/talk-index/` and `/api/summaries/`. Without the binding, those requests fall back to the files generated at build time.

Remote sync needs `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, and `D1_DATABASE_ID`. `D1_DATABASE_NAME` defaults to `cybertalks-d1-preview`. Create that database with `npx wrangler d1 create cybertalks-d1-preview`, put the id in the secret, and replace the placeholder `database_id` in `wrangler.d1-preview.jsonc` before deploying the preview worker. Do not deploy `wrangler.jsonc` for this work.

```bash
npx opennextjs-cloudflare build --config wrangler.d1-preview.jsonc
npx opennextjs-cloudflare preview --config wrangler.d1-preview.jsonc
```

Local preview uses the D1 data under `.wrangler/state`. Load it with `npx tsx scripts/d1/sync.ts --full` before starting the preview.
